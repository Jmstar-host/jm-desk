# JM Desk 架构（开源、可二次开发）

> 定位：一个**独立的本地 AI 桌面助手**。核心开源，允许二次开发：自己设计精灵形象、
> 接入自己的平台、知识库、信息源和模型。业务平台（如 MP2）只是被接入的一方。

## 1. 分层

```
┌──────── 界面层（renderer）────────┐
│ 精灵窗口 · 提示层（两圈气泡/说话） · 应用面板 │
└───────────────┬──────────────────┘
                │ IPC（只传数据，不传凭据）
┌──────── 运行时（Electron main）────────┐
│ 注册表：形象包 / 连接器 / 平台 / 知识库 / 面板应用 / 模型 │
│ 凭据保管（safeStorage：macOS 钥匙串 / Windows DPAPI）   │
│ 调度（定时收集）· 回执与「搬运记录」                     │
└──────────────────────────────────────┘
```

## 2. 扩展点

| 类型 | 作用 | 现状 |
|---|---|---|
| `character` 形象包 | 精灵长什么样 | **已实现**：放在 `<数据目录>/extensions/character/<id>/`，有两种：`kind: procedural`（导出 `build(THREE, params)`）、`kind: gltf`（模型 + 骨骼映射）。统一骨骼名：`Spine1 Head LEar REar LArm RArm LForeArm RForeArm Tail1..7` |
| 平台 API / MCP 接入 | 让助手调用外部系统 | **已实现**：「设置 › 接入」，支持 MCP（本机命令 / 网址）和 OpenAPI，见 AGENTS.md §5 |
| 业务平台 | 需求管理平台等 | **已实现**设备授权关联，见 [PLATFORM-CONNECT.md](PLATFORM-CONNECT.md) |
| 模型 | 大模型来源 | **已实现**：API（OpenAI 兼容）、本机 Claude Code / Codex / Ollama、自定义命令 |
| `connector` 信息源 | 邮件、飞书、会议、日历…… | 内置收集器在 `src/sources/`；从目录**自动加载**还在规划中 |
| `app` 面板应用 | 精灵旁边打开的小应用 | 规划中 |

`Signal` 的统一结构：`{ id, source_type, source_ref, source_url, title, occurred_at, participants, content }`，与 `src/` 里的收集器一致。

## 3. 开源核心与企业定制分开

- **开源核心**包含：
  - 原创形象「星灵 Lumi」。
  - 信息源收集器：邮件（Mailspring 本地库，只读）、飞书（通过本机 `lark-cli` 以本人身份读取）。
  - 通用的 MCP / HTTP 接入、多模型来源、平台接入协议。
- **企业定制**：例如公司知识库地址，在打包时用 `JM_DESK_PRESET` 注入（见 AGENTS.md §8），不进开源仓库。
- **开源仓库里不允许出现**：个人路径、公司内部域名、密钥、第三方受版权保护的形象。

## 4. 两圈气泡菜单由注册表生成

内圈 = 分组（互动 / 工作 / 邮箱 / 设置，可扩展）；外圈 = 该分组下的面板应用和动作。
扩展通过 `manifest.ring` 把自己挂进某个分组，不用改核心代码。

## 5. 安全底线

- 凭据只在主进程、只在钥匙串；界面层和扩展拿不到明文。
- 外部内容（邮件、聊天、知识库、好友空间）一律当资料，不当指令执行。
- 每次读取外部来源、发给模型、写入平台，都记一条「搬运记录」，精灵气泡可滚动展示，用户可查。
